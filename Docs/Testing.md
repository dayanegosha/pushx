# Проверка pushx

Актуальный аудит от 22 октября — в [Audit-2026-10-22.md](Audit-2026-10-22.md). Ниже воспроизводимые команды и план приёмки. Неотмеченный сценарий не считается проверенным. Итоговые результаты, версии инструментов и ссылки на `.xcresult` фиксируются в конце файла. Компиляция, симулятор, локальный StoreKit и тестовые сетевые ответы не заменяют проверку камеры, Health, Apple Auth и Sandbox на физических iPhone и iPad.

## Сборка и XCTest

Нужны macOS, полный Xcode с выбранными Command Line Tools, iOS Simulator runtime и XcodeGen. Проект ориентирован на iOS 17+; для текущей разработки используется Xcode 27. Сначала сгенерируйте проект:

```sh
brew install xcodegen
cd iOS
xcodegen generate
xcodebuild -project pushx.xcodeproj -scheme pushx -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

Для запуска тестов выберите доступный конкретный симулятор. Generic destination подходит для сборки, но не для выполнения XCTest:

```sh
xcrun simctl list devices available
xcodebuild -project pushx.xcodeproj -scheme pushx -showdestinations
xcodebuild -project pushx.xcodeproj -scheme pushx -destination 'platform=iOS Simulator,id=SIMULATOR_UDID' -resultBundlePath ../TestResults/pushx.xcresult test
```

Замените `SIMULATOR_UDID` на ID из вывода команд; для каждого прогона используйте новый путь `.xcresult`. Для проверки на физическом iPhone или iPad откройте `pushx.xcodeproj`, выберите Team и физическое устройство, включите Developer Mode по запросу iOS и запустите схему `pushx`.

Существующие `RepCycleTests` проверяют полный цикл, начало снизу, дрожание порогов, потерю лица/кадров, паузу, неверное время и калибровку с выбросами. `ServiceTests` используют `URLProtocol`: проверяют nonce, refresh, даты, форму RPC, пагинацию, серверные ошибки и подтверждение удаления. Они не обращаются к реальному Apple и Supabase.

## Backend

Из каталога `Backend`:

```sh
node --experimental-strip-types --test tests/delete-account.test.ts
deno check --config supabase/functions/delete-account/deno.json supabase/functions/delete-account/index.ts
deno test --config supabase/functions/delete-account/deno.json tests/apple-token.test.ts
```

SQL regression запускается только в пустой одноразовой локальной PostgreSQL БД. Не применяйте Auth fixture к рабочему Supabase:

```sh
psql "$DISPOSABLE_DATABASE_URL" -v ON_ERROR_STOP=1 -f tests/bootstrap.sql -f supabase/migrations/202610180001_pushx.sql -f supabase/migrations/202610210001_profile_display_names.sql -f tests/regression.sql
```

Покрыты запрет анонимного доступа и прямой записи, изоляция владельца, заявки/принятие/блокировки, закрытый список блокировок, рейтинг, неизменяемость UUID, пересечение тренировок, недопустимые даты/повторения и каскад удаления. Edge tests подменяют сетевые и JWT-адаптеры, проверяя порядок операций и отказ при несовпадении Apple identity. Для настоящих ключей и сети нужен отдельный прогон.

Для локальной проверки UI на симуляторе задайте `PUSHX_LOCAL_PREVIEW=1` в Xcode Scheme → Run → Arguments → Environment Variables для Debug ; Simulator показывает недоступность ARKit, не имитируя физические повторения. Проверку обязательного входа выполняйте отдельно без флага; Release с тем же флагом не должен обходить Welcome. Не заполняйте облачную историю вымышленными реальными пользователями ради скриншотов. Снимок симулятора фиксирует UI, а не точность распознавания.

## Матрица экранов и поворота

Полная инвентаризация и план Duo — в [Compatibility.md](Compatibility.md). В текущем Xcode 27.1 профиль Duo есть в `simctl list devicetypes`, а необходимый runtime 27.1 не установлен. Похожие размеры iPad не заменяют прямой тест Duo; для него нужен совместимый runtime 27.1 и запуск настоящего профиля.

- [ ] На iPad Pro 11″ (M5) и mini (A17 Pro) запущен настоящий iPad simulator profile, а не iPhone compatibility mode.
- [ ] На iPad Welcome, Home, History, Friends, Settings и Plus работают в портрете и landscape, с большим системным текстом и клавиатурой. На iPhone поворот устройства сохраняет портретный интерфейс.
- [ ] На физическом устройстве выполнено несколько повторов, затем поворот portrait → landscape → portrait: на iPad раскладка меняется, на iPhone остаётся портретной; итог не обнулился, запись после завершения одна.
- [ ] Главная не содержит ScrollView; счётчик и кнопка старта помещаются на iPhone SE, включая максимальный размер текста.
- [ ] Goal и Accent доступны на обоих iPad; значения переживают смену раскладки.
- [ ] Узкое окно iPad сохраняет прокрутку и доступ к паузе/завершению, CSV и модальные окна не падают.
- [ ] На физической камере поворот или смена её геометрии требует повторной калибровки без добавления старого незавершённого повтора.
- [ ] На настоящем профиле Duo повторены внешний/внутренний экран, раскрытие, складывание и вертикальные системные панели; до этого пункта прямая совместимость не заявляется.

## Камера на физических iPhone и iPad

Базовый набор с разными фронтальными камерами: компактный iPhone на поддерживаемой iOS, современный iPhone и физический iPad. Duo добавляется к полевой проверке отдельно после получения устройства. Зафиксируйте модель, iOS, освещение, положение устройства и ручной контрольный счёт. Для каждого сценария выполните три серии по 20 полных повторений и запишите факт / счёт приложения / пропуски / лишние повторы.

- [ ] Устройство экраном вверх, лицо видно на всём диапазоне; успешная автоматическая настройка верхней позиции.
- [ ] Обычный, медленный и быстрый комфортный темп; в контролируемом основном сценарии 20 полных повторов дают 20.
- [ ] Старт из нижнего положения не добавляет ложное первое повторение.
- [ ] Неполное движение, одиночный наклон и 30 секунд неподвижности не дают лишних очков.
- [ ] Краткое перекрытие после подтверждённой нижней фазы сохраняет цикл; без подтверждения низа или после долгой потери лица возвращение не добавляет повтор.
- [ ] Движение телефона приостанавливает подсчёт без добавления очков; после остановки требуется новая верхняя позиция.
- [ ] Второе лицо в кадре не подменяет пользователя и не добавляет очков.
- [ ] Тусклый свет, боковое освещение, очки, различный фон: ошибка калибровки/потеря лица понятны, доступен повтор настройки.
- [ ] Слишком близкая/далёкая установка, малая амплитуда и закрытая камера не позволяют притвориться успешной калибровкой.
- [ ] Пауза внизу, блокировка экрана, звонок и уход приложения в фон не дают дополнительный повтор при возврате.
- [ ] Сессия 10–15 минут не вызывает заметного перегрева, роста памяти и резкого ухудшения реакции.

Размещение устройства не должно требовать касаться экраном лицом или рисковать ударом о устройство. Алгоритм оценивает движение и не оценивает спортивную технику. Матрицу можно расширять по результатам полевых тестов; отклонения фиксируются до релиза, а не скрываются обещанием точности.

## Владельцы, синхронизация и друзья

Понадобятся развёрнутый backend и два собственных тестовых Apple аккаунта A/B.

- [ ] Release без сессии не позволяет начать тренировку; Sign in with Apple работает с живым проектом и создаёт текущий `ownerID`.
- [ ] Миграционный тест: старая запись G с `ownerID = nil` после входа A остаётся локальной, не появляется в облаке или рейтинге A. Это тест совместимости/Debug, а не гостевой сценарий Release.
- [ ] A создаёт A1 офлайн, перезапускает приложение, возвращает сеть: сервер получает A1 ровно один раз.
- [ ] Повторная отправка A1 сохраняет тот же UUID и результат, повторная загрузка не создаёт локальный дубль.
- [ ] После выхода A и входа B запись A1 не видна как история B и не загружается в B; старая локальная G не переносится в B.
- [ ] Выход/смена пользователя во время запроса не объединяют ответ A с B.
- [ ] Облачная история A восстанавливается на другом устройстве; объём свыше 1000 записей не обрезается первой страницей.
- [ ] Первое разрешение Apple сохраняет имя до обмена токена; после сетевого сбоя, refresh и выхода/повторного входа имя остаётся. Имя можно изменить в настройках; следующий вход не заменяет его исходным Apple именем.
- [ ] Старый аккаунт без имени отображается как «Участник»; кириллица и китайские имена видны в заявках, списке и рейтинге друзей.
- [ ] Истёкшая сессия обновляется; отзыв Apple credential и недействительный refresh не приводят к бесконечному повтору.
- [ ] Запрос по неверному коду, повтор заявки, incoming/outgoing и отклонение отображаются корректно.
- [ ] Принять собственную заявку нельзя; рейтинг включает друга только после принятия.
- [ ] Удаление друга и блокировка убирают его из рейтинга, собственный список блокировок позволяет снять блокировку.
- [ ] Другой аккаунт не может читать отдельные workouts, профиль или блокировки A через REST.
- [ ] День в Москве и день UTC проверены около 00:00 местного времени и UTC-полуночи; подписи рейтинга соответствуют UTC.
- [ ] Серверный отказ — старше 30 дней, пересечение, 601 повтор, слишком короткая сессия — оставляет локальный результат и показывает ошибку синхронизации.

## Apple Health на устройстве

- [ ] Чистая установка: до добровольного включения запись в Health не происходит.
- [ ] Запрос содержит только разрешение добавлять тренировки, без категорий чтения.
- [ ] Отказ не мешает счётчику и истории; повтор после изменения разрешений работает.
- [ ] Завершённая тренировка видна в «Здоровье» как силовая с ожидаемыми началом, окончанием и длительностью.
- [ ] В metadata сохранены UUID sync identifier, version 1 и число повторений; нет выдуманных калорий, пульса или дистанции.
- [ ] Двойное нажатие синхронизации, перезапуск после записи до локального подтверждения и повторная доставка сохраняют одну Health-тренировку.
- [ ] Ошибка или отзыв разрешения не помечают запись как успешно синхронизированную; локальная история сохранена.
- [ ] Выключение Health прекращает новые записи. Уже записанные тренировки остаются управляемыми в Health.
- [ ] Удаление аккаунта не стирает данные Health и не запрашивает чтение для поиска старых записей.

Интерфейс Health не обязан показывать пользовательский metadata как отдельное число отжиманий. Обещание продукта — добавление силовой тренировки, без стандартного счётчика повторений в «Здоровье».

## Подписки и удаление

Сначала проверьте локальный `pushx.storekit`, затем ту же матрицу в Sandbox / TestFlight с реальными настройками App Store Connect. Для покупки нужен опубликованный HTTPS `PRIVACY_URL`; без него кнопка покупки намеренно отключена.

- [ ] Покупка monthly/yearly открывает только Plus; цена и период соответствуют StoreKit.
- [ ] Cancel и pending не открывают Plus; unverified transaction не считается покупкой.
- [ ] После истечения/отзыва доступ закрывается, история и бесплатные функции остаются.
- [ ] Автопродление и проверенный grace period поддерживают нужный срок доступа; смена тарифа не удваивает подписку.
- [ ] После обязательного входа в pushx Restore на другом устройстве с тем же Apple аккаунтом магазина восстанавливает Plus; право покупки не зависит от friend code или клиентского флага.
- [ ] CSV содержит видимую историю в UTF-8 с корректными UUID, UTC timestamps, числом повторений и режимом; отмена экспорта безопасна.
- [ ] Terms/privacy открываются, paywall закрывается, управление подпиской доступно.
- [ ] Удаление требует свежей авторизации Apple; отмена оставляет аккаунт и локальную историю.
- [ ] Apple token от другого subject не удаляет текущий аккаунт; истёкший/повторно использованный code не считается успехом.
- [ ] Сбой Apple revoke не удаляет Supabase аккаунт; сбой удаления после revoke позволяет повтор со свежим кодом.
- [ ] Успех удаляет серверные связанные данные и локальные записи текущего аккаунта. Старые локальные записи без владельца и Health не исчезают без соответствующего действия пользователя.
- [ ] Удаление аккаунта не выдаётся за отмену подписки; системное управление подпиской остаётся понятным.

## Результаты проверки

Обновлено 22 октября 2026 года: Xcode 27.0 (`27A266a`), SDK iOS 27.0, deployment target iOS / iPadOS 17.0.

### Календарь серии в статистике

Полный подписанный модульный прогон после добавления календаря: **86 / 86**, без пропусков (`PushxCalendarUnit.xcresult`). Три дополнительные проверки общего дневного агрегатора покрывают неполные дни, границы локальных суток, исключение будущих/некорректных записей и длительную историю. Календарь использует тот же дневной агрегатор, что и серия.

В production UI проверен переход с главной в календарь и выключенное исходное напоминание на iPhone SE, runtime 26.5, и iPad Pro 11″, runtime 27.0 (`PushxStreakCalendarSEUI.xcresult`, `PushxCalendarPadControls.xcresult`). Проверка главной без прокрутки и максимального текста на SE также прошла. Отдельная нативная сборка с демонстрационной историей проверила обе темы, выбор сегодняшнего и вчерашнего дня, сумму 5, переходы между месяцами, отсутствие очков в пустом прошлом месяце и недоступность будущего дня (`PushxStatisticsReviewConfirmed.xcresult`).

В изолированной нативной сборке прошли **6 / 6** проверок последнего экрана тренировки (`PushxNativeFinalReview.xcresult`): равные координаты логотипа на двух вводных экранах, доступность продолжения при максимальном тексте, закреплённая цифра в пяти состояниях, отсутствие уведомления при краткой потере лица, одно уведомление при движении, однократный автоматический старт. Для снимков главной использована отдельная демонстрационная история из семи дней по пять повторений; в production имитации нет.

### Серия дней и ежедневное напоминание

22 октября: полный подписанный прогон на iPad Pro 11″, runtime 27.0 — **83 / 83**, без пропусков (`PushxStreakReminderUnit.xcresult`). Добавлены девять проверок серии: порог 4/5, сумма подходов, пропущенный день, продолжение вчерашней серии, будущие записи, високосный день, переходы DST, 800 дней подряд и границы локальных суток. Девять проверок напоминаний покрывают выключенное исходное состояние, добровольное разрешение, замену одного запроса, отказ iOS, выключение во время разрешения/добавления, последнее выбранное время и ошибки планирования. Сам запрос проверен: повтор каждый день по местным часам и минутам, без звука и badge. Это не проверка доставки настоящего уведомления через сутки.

Release собирается без подписи (`pushx-final-streak-release.log`). Новая копия **pushx test** с серией, настройками напоминаний и последним экраном тренировки установлена и запущена на физическом iPhone 17 Pro. Промежуточные снимки с изображениями телефона и человека, крупной старой цифрой и постоянными подсказками больше не соответствуют интерфейсу.

### Нижняя фаза и обновлённый экран тренировки

22 октября: полный подписанный модульный прогон на iPad Pro 11″, runtime 27.0 — **65 / 65**, без пропусков (`PushxStableWorkoutUnit.xcresult`). Проверены короткая и долгая потеря лица внизу, возврат с новым AR-якорем, запрет ложного повтора после одного нижнего выброса, выбор центральной глубины, движение телефона и выдержка неподвижности. Это проверки алгоритма на входных данных; они не измеряют точность настоящей камеры.

Пользовательская серия **5 / 5** выполнена на промежуточной тестовой сборке с исправлением нижней фазы. Более строгая проверка нижней выдержки, остановка при движении телефона, автоматический старт и новое оформление добавлены позднее; эта серия не является их полевой проверкой.

В production UI на iPad Pro 11″ прошли **3 / 3** сценария: максимальный текст и доступность старта/закрытия, поворот, отсутствие ручного подсчёта и вымышленной записи на Simulator (`PushxStableWorkoutUI.xcresult`).

Текущий Release собирается без подписи (`pushx-stable-workout-release.log`). Обновлённая development-копия **pushx test** установлена на физический iPhone. Автоматический запуск после установки отклонён системой, поскольку телефон был заблокирован; новый интерфейс и движение телефона ещё требуют ручной проверки на устройстве.

### Переход на ARKit без превью

На iPhone 17 Pro прошли **4 / 4** UI-сценария: фиксированная главная и портретная блокировка, смена языка RU → EN → ZH с сохранением настроек, максимальный текст, отсутствие ручного подсчёта и честная недоступность ARKit на Simulator (`PushxFinalInteractionTests.xcresult`). На iPad Pro 11″ также прошли **2 / 2** проверки: смена языка без выхода из настроек и поворот с доступным закрытием (`PushxPadARInterface.xcresult`). ### Проверка до перехода на ARKit

- Полный модульный прогон на iPhone 17 Pro, runtime 27.0: **43 / 43**, без пропусков. Подписанный Simulator проверил настоящие операции Keychain: повторный вход без имени Apple, изоляцию аккаунтов, ручное переименование и удаление кеша. Локальное подтверждение — `profile-revision-signed-tests.xcresult`.
- Новые контракты проверяют нормализацию Unicode, отклонение скрытых управляющих символов, RPC изменения имени и совместимость старых профилей с `NULL`.
- UI на iPhone 17 Pro: первый вход в обеих темах, максимальный текст, сохранение трёх повторений и повторный запуск, три языка — **4 / 4** (`PushxVerifiedTests.xcresult`).
- На iPhone SE, runtime 26.5, прошли фиксированная главная и сохранение двух повторений при запросе landscape: приложение остаётся в портрете. Максимальный текст сначала выявил ошибку области нажатия; после исправления отдельный сценарий прошёл, кнопка старта открывает тренировку (`PushxPortraitSETests.xcresult`, `PushxSEAccessibilityFixTests.xcresult`).
- Снимки Geologica, монохромной волны, кнопки Apple высотой 44 points, друзей и редактирования имени сняты с iPhone 17 Pro и iPad Pro 11″ в обеих темах. Длинные русские и китайские имена не обрезаются. На iPad дополнительно снята главная в landscape.

На iPhone разрешён только портрет; iPad сохраняет четыре ориентации. Debug-флаги `PUSHX_LOCAL_PREVIEW` и `PUSHX_RESET_DATA` отсутствуют в Release executable.

На физическом iPhone 17 Pro с iOS 27.0.1 установлена и запущена отдельная development-копия **pushx test**, bundle ID `app.forma.pushups.local`. Она подписана Personal Team, сохраняет HealthKit, использует реальный локальный счётчик и пропускает облачный вход только в этой тестовой копии. Production-проект сохраняет обязательный вход Apple и свои entitlements. Полную сборку Personal Team не подписывает: Xcode сообщает, что Sign in with Apple для неё недоступен. Запуск приложения на устройстве ещё не подтверждает точность камеры или успешную запись тренировки в Health.

Backend: обе миграции и PostgreSQL regression проходят на новой тестовой базе. Проверены права на изменение имени, Unicode, старые профили, имена друзей и отсутствие доступа к чужим данным. **10 / 10** Edge-тестов и Deno typecheck проходят.
