# Проверка UPRA

Это воспроизводимые команды и план приёмки. Неотмеченный сценарий не считается проверенным. Итоговые результаты, версии инструментов и ссылки на `.xcresult` фиксируются в конце файла. Компиляция, симулятор, локальный StoreKit и тестовые сетевые ответы не заменяют проверку камеры, Health, Apple Auth и Sandbox на физических iPhone и iPad.

## Сборка и XCTest

Нужны macOS, полный Xcode с выбранными Command Line Tools, iOS Simulator runtime и XcodeGen. Проект ориентирован на iOS 17+; для текущей разработки используется Xcode 27. Сначала сгенерируйте проект:

```sh
brew install xcodegen
cd iOS
xcodegen generate
xcodebuild -project Forma.xcodeproj -scheme Forma -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

Для запуска тестов выберите доступный конкретный симулятор. Generic destination подходит для сборки, но не для выполнения XCTest:

```sh
xcrun simctl list devices available
xcodebuild -project Forma.xcodeproj -scheme Forma -showdestinations
xcodebuild -project Forma.xcodeproj -scheme Forma -destination 'platform=iOS Simulator,id=SIMULATOR_UDID' -resultBundlePath ../TestResults/Forma.xcresult test
```

Замените `SIMULATOR_UDID` на ID из вывода команд; для каждого прогона используйте новый путь `.xcresult`. Для проверки на физическом iPhone или iPad откройте `Forma.xcodeproj`, выберите Team и физическое устройство, включите Developer Mode по запросу iOS и запустите схему `Forma`.

Существующие `RepCycleTests` проверяют полный цикл, начало снизу, дрожание порогов, потерю лица/кадров, паузу, неверное время и калибровку с выбросами. `ServiceTests` используют `URLProtocol`: проверяют nonce, refresh, даты, форму RPC, пагинацию, серверные ошибки и подтверждение удаления. Они не обращаются к реальному Apple и Supabase.

## Backend

Из каталога `Backend`:

```sh
node --experimental-strip-types --test tests/delete-account.test.ts
deno check --config supabase/functions/delete-account/deno.json supabase/functions/delete-account/index.ts
```

SQL regression запускается только в пустой одноразовой локальной PostgreSQL БД. Не применяйте Auth fixture к рабочему Supabase:

```sh
psql "$DISPOSABLE_DATABASE_URL" -v ON_ERROR_STOP=1 -f tests/bootstrap.sql -f supabase/migrations/202610180001_forma.sql -f tests/regression.sql
```

Покрыты запрет анонимного доступа и прямой записи, изоляция владельца, заявки/принятие/блокировки, закрытый список блокировок, рейтинг, неизменяемость UUID, пересечение тренировок, недопустимые даты/повторения и каскад удаления. Edge tests подменяют сетевые и JWT-адаптеры, проверяя порядок операций и отказ при несовпадении Apple identity. Для настоящих ключей и сети нужен отдельный прогон.

## Интерфейс и локальная история

| Сценарий | Ожидаемый результат |
| --- | --- |
| Чистая установка Release без сервера | Welcome показывает недоступность входа; основной интерфейс закрыт, требуется настройка сервера |
| Первый запуск с настроенным сервером | Обязательный вход Apple без кнопки пропуска; отмена оставляет Welcome, успех открывает приложение |
| Следующий запуск после входа | Сессия восстанавливается; постоянный повтор Apple диалога не требуется |
| Выход / недействительная сессия | Возврат к экрану входа, чужая история не показывается |
| `UPRA_LOCAL_PREVIEW=1` | В Debug доступен локальный UI preview, Release продолжает требовать вход |
| RU, EN, 简体中文 и системный язык | Все экраны, ошибки, permission strings и числа понятны; ключи локализации не видны |
| Светлая, тёмная и системная темы | Читаемые контраст и состояния кнопок на всех экранах |
| VoiceOver и увеличенный текст | Элементы имеют названия; доступ к завершению, настройкам и закрытию Plus сохраняется |
| Касания, пауза, продолжение и завершение | Правильный итог; режим явно обозначен; одна запись в истории |
| Выход из активной сессии, сворачивание, прерывание камеры | Нет фоновых повторений; возобновление требует понятного действия |
| Принудительное закрытие после нескольких повторов | При запуске восстановлен один ненулевой черновик, без дублей |
| Ошибка локального сохранения | Видимая ошибка, отсутствие ложного сообщения об успешном сохранении |
| Голос выключен/включён, три языка, музыка параллельно | Правильное число и язык, нет накопленной очереди устаревших чисел |
| Отказ в камере и повторное разрешение в iOS | Доступен touch mode; восстановление камеры без переустановки |

Для локальной проверки UI на симуляторе задайте `UPRA_LOCAL_PREVIEW=1` в Xcode Scheme → Run → Arguments → Environment Variables для Debug и используйте режим касаний. Проверку обязательного входа выполняйте отдельно без флага; Release с тем же флагом не должен обходить Welcome. Не заполняйте облачную историю вымышленными реальными пользователями ради скриншотов. Снимок симулятора фиксирует UI, а не точность распознавания.

## Матрица экранов и поворота

Полная инвентаризация и план Duo — в [Compatibility.md](Compatibility.md). На текущем Xcode 27.0 нет Duo в `simctl list devicetypes`, а runtime 27.1 не установлен. Похожие размеры iPad не заменяют прямой тест Duo; для него нужен Xcode 27.1 и настоящий профиль.

- [ ] На iPad Pro 11″ (M5) и mini (A17 Pro) запущен настоящий iPad simulator profile, а не iPhone compatibility mode.
- [ ] Welcome, Home, History, Friends, Settings и Plus работают в портрете и landscape, с большой системной гарнитурой и клавиатурой.
- [ ] В режиме касаний выполнено несколько повторов, затем поворот portrait → landscape → portrait: итог не обнулился, запись после завершения одна.
- [ ] Goal и Accent доступны на обоих iPad; значения переживают смену раскладки.
- [ ] Узкое окно iPad сохраняет прокрутку и доступ к паузе/завершению, CSV и модальные окна не падают.
- [ ] На физической камере поворот или смена её геометрии требует повторной калибровки без добавления старого незавершённого повтора.
- [ ] На настоящем профиле Duo повторены внешний/внутренний экран, раскрытие, складывание и вертикальные системные панели; до этого пункта прямая совместимость не заявляется.

## Камера на физических iPhone и iPad

Базовый набор с разными фронтальными камерами: компактный iPhone на поддерживаемой iOS, современный iPhone и физический iPad. Duo добавляется к полевой проверке отдельно после получения устройства. Зафиксируйте модель, iOS, освещение, положение устройства и ручной контрольный счёт. Для каждого сценария выполните три серии по 20 полных повторений и запишите факт / счёт приложения / пропуски / лишние повторы.

- [ ] Устройство экраном вверх, лицо видно на всём диапазоне; успешная калибровка верхнего и нижнего положения.
- [ ] Обычный, медленный и быстрый комфортный темп; в контролируемом основном сценарии 20 полных повторов дают 20.
- [ ] Старт из нижнего положения не добавляет ложное первое повторение.
- [ ] Неполное движение, одиночный наклон и 30 секунд неподвижности не дают лишних очков.
- [ ] Уход лица из кадра между фазами и возвращение не завершают старый повтор.
- [ ] Второе лицо в кадре не подменяет пользователя и не добавляет очков.
- [ ] Тусклый свет, боковое освещение, очки, различный фон: ошибка калибровки/потеря лица понятны, доступен повтор настройки.
- [ ] Слишком близкая/далёкая установка, малая амплитуда и закрытая камера не позволяют притвориться успешной калибровкой.
- [ ] Пауза внизу, блокировка экрана, звонок и уход приложения в фон не дают дополнительный повтор при возврате.
- [ ] Сессия 10–15 минут не вызывает заметного перегрева, роста памяти и резкого ухудшения реакции.

Размещение устройства не должно требовать касаться экраном лицом или рисковать ударом о устройство. Алгоритм оценивает движение и не оценивает спортивную технику. Матрицу можно расширять по результатам полевых тестов; отклонения фиксируются до релиза, а не скрываются обещанием точности.

## Владельцы, синхронизация и друзья

Понадобятся развёрнутый backend и два собственных тестовых Apple аккаунта A/B.

- [ ] Release без сессии не позволяет начать тренировку; Sign in with Apple работает с живым проектом и создаёт текущий `ownerID`.
- [ ] Миграционный тест: старая запись G с `ownerID = nil` после входа A остаётся локальной, не появляется в облаке или рейтинге A. Это тест совместимости/Debug, а не гостевой сценарий Release.
- [ ] A создаёт A1 офлайн, перезапускает приложение, возвращает сеть: сервер получает A1 ровно один раз.
- [ ] Повторная отправка A1 сохраняет тот же UUID и результат, повторная загрузка не создаёт локальный дубль.
- [ ] После выхода A и входа B запись A1 не видна как история B и не загружается в B; старая локальная G не переносится в B.
- [ ] Выход/смена пользователя во время запроса не объединяют ответ A с B.
- [ ] Облачная история A восстанавливается на другом устройстве; объём свыше 1000 записей не обрезается первой страницей.
- [ ] Истёкшая сессия обновляется; отзыв Apple credential и недействительный refresh не приводят к бесконечному повтору.
- [ ] Запрос по неверному коду, повтор заявки, incoming/outgoing и отклонение отображаются корректно.
- [ ] Принять собственную заявку нельзя; рейтинг включает друга только после принятия.
- [ ] Удаление друга и блокировка убирают его из рейтинга, собственный список блокировок позволяет снять блокировку.
- [ ] Другой аккаунт не может читать отдельные workouts, профиль или блокировки A через REST.
- [ ] День в Москве и день UTC проверены около 00:00 местного времени и UTC-полуночи; подписи рейтинга соответствуют UTC.
- [ ] Серверный отказ — старше 30 дней, пересечение, 601 повтор, слишком короткая сессия — оставляет локальный результат и показывает ошибку синхронизации.

## Apple Health на устройстве

- [ ] Чистая установка: до добровольного включения запись в Health не происходит.
- [ ] Запрос содержит только разрешение добавлять тренировки, без категорий чтения.
- [ ] Отказ не мешает счётчику и истории; повтор после изменения разрешений работает.
- [ ] Завершённая тренировка видна в «Здоровье» как силовая с ожидаемыми началом, окончанием и длительностью.
- [ ] В metadata сохранены UUID sync identifier, version 1 и число повторений; нет выдуманных калорий, пульса или дистанции.
- [ ] Двойное нажатие синхронизации, перезапуск после записи до локального подтверждения и повторная доставка сохраняют одну Health-тренировку.
- [ ] Ошибка или отзыв разрешения не помечают запись как успешно синхронизированную; локальная история сохранена.
- [ ] Выключение Health прекращает новые записи. Уже записанные тренировки остаются управляемыми в Health.
- [ ] Удаление аккаунта не стирает данные Health и не запрашивает чтение для поиска старых записей.

Интерфейс Health не обязан показывать пользовательский metadata как отдельное число отжиманий. Обещание продукта — добавление силовой тренировки, без стандартного счётчика повторений в «Здоровье».

## Подписки и удаление

Сначала проверьте локальный `Forma.storekit`, затем ту же матрицу в Sandbox / TestFlight с реальными настройками App Store Connect. Для покупки нужен опубликованный HTTPS `PRIVACY_URL`; без него кнопка покупки намеренно отключена.

- [ ] Покупка monthly/yearly открывает только Plus; цена и период соответствуют StoreKit.
- [ ] Cancel и pending не открывают Plus; unverified transaction не считается покупкой.
- [ ] После истечения/отзыва доступ закрывается, история и бесплатные функции остаются.
- [ ] Автопродление и проверенный grace period поддерживают нужный срок доступа; смена тарифа не удваивает подписку.
- [ ] После обязательного входа в UPRA Restore на другом устройстве с тем же Apple аккаунтом магазина восстанавливает Plus; право покупки не зависит от friend code или клиентского флага.
- [ ] CSV содержит видимую историю в UTF-8 с корректными UUID, UTC timestamps, числом повторений и режимом; отмена экспорта безопасна.
- [ ] Terms/privacy открываются, paywall закрывается, управление подпиской доступно.
- [ ] Удаление требует свежей авторизации Apple; отмена оставляет аккаунт и локальную историю.
- [ ] Apple token от другого subject не удаляет текущий аккаунт; истёкший/повторно использованный code не считается успехом.
- [ ] Сбой Apple revoke не удаляет Supabase аккаунт; сбой удаления после revoke позволяет повтор со свежим кодом.
- [ ] Успех удаляет серверные связанные данные и локальные записи текущего аккаунта. Старые локальные записи без владельца и Health не исчезают без соответствующего действия пользователя.
- [ ] Удаление аккаунта не выдаётся за отмену подписки; системное управление подпиской остаётся понятным.

## Результаты проверки

Проверено 19 октября 2026 года: Xcode 27.0 (`27A266a`), SDK iOS 27.0, deployment target iOS / iPadOS 17.0. Устройства ниже — профили Simulator с runtime 26.5.

| Профиль | Модульные тесты | UI-тесты |
| --- | --- | --- |
| iPhone 17 Pro | 38 / 38 | 6 / 6 |
| iPhone SE 3-го поколения | — | 6 / 6 |
| iPad Pro 11″ (M5) | 38 / 38 | 5 / 5 |
| iPad mini (A17 Pro) | — | 5 / 5 |

Это 38 уникальных модульных сценариев, повторённых на двух профилях. Они проверяют цикл отжимания, калибровку и смену геометрии, отсев старых кадров, REST-контракты, локальное восстановление и изоляцию владельцев. UI-сценарии проверяют обязательный первый вход, Goal/Accent, три языка, сохранение после перезапуска и поворот без потери числа повторов. На iPhone дополнительно пройден сценарий максимального размера текста.

После усиления проверки поворота выполнены отдельные повторы `testRotationKeepsWorkoutAndControlsReachable` на чистом профиле iPhone 17 Pro и на iPad Pro 11″: по **1 / 1**, без ошибок. Тест проверяет landscape-пропорции `app.frame`, возврат в портрет, доступность управления и сохранение двух повторений; журналы содержат события `Interface orientation changed`. Подтверждение — локальные `FreshLandscapeTests.xcresult`, `FinalTabletRotationTests.xcresult` и соответствующие журналы. Это повторы существующего UI-сценария, а не дополнительные уникальные тесты. На ранее использованном профиле iPhone Simulator интерфейс не поворачивался; усиленная проверка выявила это, повтор на чистом профиле прошёл с тем же кодом.

Release-сборка `generic/platform=iOS` проходит без подписи. В собранном Info.plist: `UIDeviceFamily = [1, 2]`, минимум 17.0, Onest зарегистрирован. Debug-флаги `UPRA_LOCAL_PREVIEW` и `FORMA_RESET_DATA` отсутствуют в Release executable.

Backend: PostgreSQL regression, 10 Edge-тестов и Deno typecheck проходят; команда Deno использует явный import map. CI: [checks](https://github.com/dayanegosha/upra-ios/actions).

Снимки фактических профилей находятся в [Screenshots](Screenshots). В тренировочных UI-тестах используется явный режим касаний и локальный Debug preview. Чистый первый запуск проверяется отдельно без этого флага. Эти проверки не подтверждают точность физической камеры или живые Apple Auth / Health / App Store интеграции; соответствующие пункты приёмки выше остаются неотмеченными. Прямой прогон Duo не выполнен: нужен Xcode 27.1 и профиль Duo.

Перед публикацией остаются развёртывание Supabase и настройка Apple provider, живой вход/refresh/удаление аккаунта, подписанные архив и TestFlight, Sandbox-покупки, проверка камеры и Health на физических устройствах, заполнение и публикация политики конфиденциальности. Отсутствие backend блокирует обязательный вход в Release. Для заявления оптимизации Duo отдельно нужны его настоящий Simulator и физическая проверка переходов камер; текущие iPad-прогоны эту задачу не закрывают. Полный список — в [AppStore.md](AppStore.md).
